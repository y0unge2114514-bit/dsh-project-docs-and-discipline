# v0.3.4

发布脚本自己出过一次事故：它报告 v0.3.3 发布成功，四个步骤全打了 ✓，但 Release 根本没建起来——GitHub 返回的是 500，响应体为空。

原因很简单，也很难看：脚本用 `curl -s` 取响应，然后只检查了 curl 的退出码。`curl` 在 HTTP 404 / 500 时退出码仍然是 0，于是一次彻底失败的请求被读成了成功。这正是这个插件一直在教别人别犯的错——把「命令没报错」当成「事情做成了」。

## 修正

- **curl 一律加 `--fail-with-body`**：HTTP 4xx / 5xx 现在会变成非零退出码，失败不再被静默吞掉。
- **建 Release 要求响应里有数字 `id`**；**回读要求响应里有字符串 `html_url`**。两项任一缺失即判失败，并带出响应片段（空响应会明说「空响应体」，而不是留白让人以为是没报错）。
- 两处失败各给 hint，说明是哪一环、看到的是什么。

## 测试

17 套，332 项。

`test/test-release.mjs` 从 27 项增到 30 项，新增三条针对这次事故的用例：

- curl 退出码为 0 但响应体为空 → 必须判失败（就是 500 空响应的真实形状）
- 回读拿到 `{"message":"Not Found"}` 而不是 `html_url` → 必须判失败
- 计划里的两条 curl 都必须带 `--fail-with-body`

第三条防的是回归：将来有人为了兼容旧 curl 把这参数摘掉，测试会立刻拦下。
