# 上游 skill 取舍记录

来源：[aicodeking/deepseek-stack](https://github.com/aicodeking/deepseek-stack)（MIT，29 个 `SKILL.md`）。
本地副本：`.dsh-docs/.upstream-deepseek-stack/skills/`（不进本仓库）。

## 为什么要吸收

那些 skill 总结了 agent 的几类通病：跳过计划、没跑就说修好了、同一个错反复试、长任务跑偏、为了过检查削弱测试。
规则本身是对的。

**但它们只被「读」，不被「执行」。** 模型可以加载 `ds-verify-loop`，跳过第 4 步（读真实报错）和第 9 步（贴输出），没有任何东西会发现。
`SKILL.md` 写着「没有输出不算证据」——没有东西在检查。

本插件存在的意义就是补这个缺口，所以吸收的不是 skill 的**文字**，而是其中**能被程序判定**的部分。

## 判断标准

一条规则能被吸收，需要满足三个条件：

1. **有可观察的信号**：工具调用、文件内容、命令字符串、回复文本
2. **判据确定**：同样的输入永远得到同样的结论，不依赖对意图的理解
3. **误报代价可控**：拦错了能一眼看出并重发通过

不满足的（写作风格、设计判断、依赖特定基础设施）留在提示词或干脆不做。

## 逐条决定

### 已吸收为代码门禁（`lib/skill-gate.js`）

| 上游 | 判定方式 | 位置 |
| --- | --- | --- |
| `ds-verify-loop`：「达到 5 轮未通过就停」 | 统计**真实检查命令**的连续失败数，达阈值后 steer 一次要求贴完整错误与根因 | `createFailureTracker` + `stopMessage` |
| `ds-unstick`：「同一错误 2 次后必须先测假设」 | 失败指纹相同即触发，要求写出共同假设并用探针验证 | 同上 |
| `ds-verify-loop`：「绝不削弱 / 跳过 / 删除测试」 | 写测试文件前重建改动后的内容，对比断言数量与 skip 标记；命中则**拒绝写入** | `weakensTest` + `tools.guard` |
| `ds-plan-loop`：「改动跨文件先给编号计划」 | 统计本轮**真实写过**的生产代码文件数，达 2 个时提醒一次 | `planThreshold` |

**关于阈值**：上游写 5 轮，这里用 **3 轮**。原因不是随意收紧——本插件已有断路器在同一失败 2 次时跳闸，到第 3 次时 agent 要么在推进（错误变了），要么在循环（没变）。等到 5 只是多两次失败的编辑，不产生新信息。

### 只进提示词（已写入 `DISCIPLINE_PROMPT`）

这些是**判断类**规则，写不成可靠的检查：

| 上游 | 为什么不代码化 |
| --- | --- |
| `ds-mode` | 工作风格（先复述、先读后改、小步验证），是整体倾向 |
| `ds-principles` 21 条 | 设计取舍，需要理解意图；「数据形状优先」「低读者负担」无法判定 |
| `ds-blast-radius` | 分级证明（level 1-5）是报告格式，可作为提示但不该拦 |
| `ds-tdd` | 「先写失败测试」在会话历史里能看出顺序，但你的很多改动是配置 / 文档类，硬拦会误伤 |
| `ds-context-reset` / `ds-ledger` | PROGRESS.md / ledger 的**存在性**可以查，但「内容是否诚实」不行；当前以提示为主 |

### 不吸收

| 上游 | 原因 |
| --- | --- |
| `ds-ship` `ds-ready` `ds-pr` `ds-watch-pr` `ds-adopt` `ds-revive` `ds-pr-comments` | 依赖 `gh` CLI 与 GitHub PR 流程。本工作区是直接推 `main`，没有 PR 可审 |

## 与已有门禁的关系

吸收时**没有重复造轮子**，几个规则挂在既有机制上：

- 失败计数复用 `tools/result` 的 `toolFailed()` 判定，与断路器用同一份观察，两个门禁不会对「什么算失败」产生分歧
- 「跨文件先给计划」与已有的 `planGate`（要求产出过计划文档）互补：前者看**实际改动面**，后者看**有没有写计划**
- 所有新提醒都经过 `userNotice()`，带 `source.kind`，避免无标签上下文导致会话损坏（这是 2026-11-01 踩过的坑）

## 配置

`cordis.patch.yml` 的 `skillGate: true`（默认开）。设为 `false` 关闭全部四条规则。

## 已知限制

1. **只认 `write` / `edit`**：`multi_edit` / `apply_patch` 无法可靠重建改动后的内容，测试削弱检测对它们不生效
2. **计划提醒只看文件数**：一个文件改 500 行不触发，两个文件各改 1 行会触发——这是上游 skill 的原意（跨文件才有协调成本）
3. **停止消息只说一次**：重复提醒会被模型学会跳过，所以宁可少说
