# 编程纪律（DSH 项目文档）

**适用**：本 harness 里所有项目、所有 Agent、所有会话。目标是让「接手 → 开工 → 收尾」可复现，减少多 Agent 互相覆写与重复劳动。
**强制入口**：每个会话的系统提示里都有一段「项目文档纪律」；本页是完整版，冲突时以本页为准。
**版本**：v2.2（2026-11-01）。修订流程见文末「自我完善」。

## 0. 一条铁律

**先读后写，先认领后动手，收尾必留痕。** 任何跳过这三步的改动都视为违规。

### 0.1 机制保障（自动执行）

- **系统提示注入**：每个会话都带一段「项目文档纪律」摘要（约 300 token），新 Agent 不需要被提醒。
- **首次工具调用守卫**：每个 Agent 在新会话里**第一次调用任意工具时会被拦截一次**（默认 `disciplineGuardMode: early`；设 `write` 则退回只拦 `write`/`edit`），返回「先调用 project_docs」的提示；拦截只发生一次，不会卡住流程。守卫状态持久化在 `storeDir/.discipline-guard.json`，插件重载不丢；会话历史里已调过 `project_docs` 的不再拦；`origin: 'subagent'` 的子代理放行；插件注册前已存在的会话不受影响。
- **关闭方式**：插件 config 设 `disciplinePrompt: false`（关提示）或 `disciplineGuard: false`（关守卫），不推荐同时关。
- **无认领禁写守卫**（`claimGuard`，默认开启）：本会话的写操作（`write` / `edit` / `ops_bash` / `pwsh` 等）会按 `cwd` 与参数里的路径定位所属项目；若项目**已有他人活跃认领**而本会话没有，直接拒绝并列出对方 `agent → scope`；若项目**没人认领**，第一次写操作提示一次再放行。子代理放行（由父代理认领），认领过期即失效。可用 `claimGuard: false` 关闭。
- **超时守卫**（`timeoutGuard`，默认开启）：调用里如果自带超过 `timeoutWarnAboveSeconds`（默认 120 秒）的超时参数（`timeoutMs` / `timeout` / `timeout_seconds` / `waitMs` 等），**第一次会被直接拒绝**并给出「先并发 / 再换更快的做法 / 最后才等」的决策顺序；同一 Agent 只拦一次，重发即放行。慢调用（默认 > 20 秒，`slowCallWarnSeconds`）结束后，运行时上下文会出现 `**效率监督：上一次调用花了 N 分钟**` 的提醒，持续 10 分钟。
- 这几层是「提醒 + 一次强制 + 认领门禁 + 超时门禁」，不是无限阻挠；纪律本身仍靠本页与留言板维护。

### 0.2 思考收束（每段思考下方的加粗「下一步」）

- **每段思考结束、发起工具调用之前，先在可见文本第一行写一句加粗短句**：`**下一步：<≤20 字>**`；必要时在后面紧跟一句依据。
- 位置固定为**思维链正下方**（模型可见文本位于 reasoning 块之后），人和后续 Agent 不用读完整思维链就知道正在干什么。
- **一次思考只推进一步**（3–5 个要点以内），不要一次推演整条链路；想不完就先把结论落到「下一步」行，边做边想。
- **批量调用先写「本批」**：同一轮要连发多个工具时，先写一行 `**本批：<目标>**`（例：`**本批：读 3 个文件确认接口**`），说明这一串操作为了什么，再逐条调用；不写「本批」就分批，一批只干一件事。
- 多步任务每一步都写；纯回答、没有工具调用时不必写。
- 这是给人看的进度锚点，不是空话：写清「要做什么 + 为什么」，例如 `**下一步：先跑 store 测试，确认 CAS 未破坏。**`

### 0.3 文档监督（周期性提醒 + 读文档前不许动项目）

**背景**：有个改进 TCP 性能的 Agent 一路上都不知道项目跑在**校园网内网**里——它没读（或读完就忘了）项目文档里的开发背景，只凭「性能经验」直接调参。文档监督把「记得读」变成机制：

- **每个 Agent 的运行时上下文里有一条动态提醒**（作用域 `system-prompt/assemble` waterfall，每次模型请求前重新求值）：
  - 本会话还没碰过文档：`**文档监督：本会话还没查项目文档** — 先 list_projects 定位项目，读 PROJECT.md / COLLAB.md（红线、开发背景，如网络环境是不是校园网内网、限速与端口策略），再动手`；
  - 超过 25 分钟没复查：提醒确认开发背景仍然成立，有新结论用 `write_doc` / `append_doc` 回写；
  - 超过 2 小时：提醒整理文档——过时的进度 / 交接 / 日志按归档规则进 archive，被取代的旧稿删掉，还在做的写进 `WORKLOG.md`。
  - 文档新鲜时该行消失，不占提示词。
- **读文档前不许动项目**（`requireDocsBeforeWrite`，默认开启）：会话第一次对某项目写文件 / 跑命令（`write` / `edit` / `ops_bash` / `pwsh` 等）时，如果没读过该项目的 `PROJECT.md` 或 `COLLAB.md`，**直接拒绝**并提示先去读；读一份即可继续。子代理同样生效（真正动手的常是子代理）。
- 判断「读过」：本会话通过 `project_docs → read_doc` 成功读过（内存记录 + 重载后回看会话历史）；用 `read` 直接打开库文件不算。
- 因此**别把开发背景只写在聊天里**：网络环境、限速 / 端口策略、上游约束这类「不知道就会做错」的事实，必须落在项目文档的 PROJECT.md 或 COLLAB.md 里，否则监督机制没有东西可提醒。
- 可用 config `supervisor: false` / `requireDocsBeforeWrite: false` 关闭。

### 0.4 先查历史，别重复发明轮子（`search_docs`）

**背景**：Agent 反复重提「已经归档 / 已经解决」的旧问题，把上次的结论再推一遍，token 白烧、研发变慢。

- **动手前先查**：在重新分析一个旧 bug / 旧问题、或重写一个疑似已存在的脚本之前，先 `project_docs → search_docs`（关键词，默认含归档文档，可 `project` 过滤）查一遍结论；脚本 / 工具用 `find_tools` 查公共工具库。
- **归档不等于删除**：`archive/` 里的文档仍在库内、仍可检索，只是不进常规阅读流；命中带 `[已归档]` 标记，排在现役文档之后。
- **零命中才从头做**：`search_docs` 命中 0 条会明确说「库里没有现成结论，可以放心从头研究」；这时再从零推理，研究完把结论写回项目文档，让下一个人不用再查一遍。
- 这条同时写进了系统提示纪律和文档监督提醒（本会话没查文档 / 25 分钟未复查时附一句「先 search_docs 查现成结论」）。
- **鼓励查阅而不是重推**：读一份现成文档通常几百 token，重新推一遍是几千到几万；文档里有结论就引用它，不要凭记忆重述。

### 0.5 认领即协作（同项目并行必须互相通报，2026-10-19）

**背景**：有了认领之后，两个 Agent 容易变成「各占一块地、老死不相往来」——各自的进度只在自己的聊天里，谁也不知道对方下一步要动什么，覆盖、重复研究、反向修改照样发生。认领是**协作通道**，不是分界线：

- **claim_work 之后立刻通报**：用 `project_docs_write → post_message`（`to: 对方 agent`，`message_kind: "claim"`）说明你负责哪一块、下一步做什么；不要只在心里划范围。
- **每完成一个里程碑就更新认领**：`claim_work`（`claim_id` + `progress` + `next_step`；只有显式传 `ttl_minutes` 才续租，不传保留剩余租期）写清「已完成到哪、下一步做什么」；`list_claims` / `list_projects` 里对方能直接看到。
- **动手之前看对方进度**：`list_claims` 多于一条 = 有协作对象；对方进度变了先按对方最新状态调整，发现范围冲突先留言协商，**不要直接覆盖**对方正在改的文件。
- **监督者会提醒**：同项目有他人认领时，本会话周期出现 `**协作提醒：项目 X 上你和 Y 同时有认领**`（`supervisorCollabMinutes`，默认 20 分钟一次），附对方 scope / 进度 / 下一步。
- **收工**：`release_claim` + Agent 留言板 handoff；一方先做完也要告诉对方「我这边释放了，范围还给你」，不要默默消失。

### 0.6 效率纪律：不要用超时去等（2026-10-21）

**背景**：Agent 普遍预设「几分钟」级别的操作超时，然后原地等完——搜索几十秒、克隆几分钟、脚本跑到天荒地老。等待期间什么都没做，这是开发速度的主要浪费。

**决策顺序（强制，从上往下判断，不要跳步）**：

1. **能不能并发？** 同一轮里彼此独立的调用一起发（写「**本批**」说明这批在做什么）；大块工作拆给 `subagent` / `workflow` 并行；读多个文件/查多个源时不要一个个来。
2. **有没有更快的等价做法？** 缩小范围（只查需要的目录 / 只取需要的字段）、只取片段（`read` 带 offset/limit、API 分页、`head`）、换镜像或换接口（GitHub 走 `gha.sh`、npm 用镜像）、加 `--depth 1` / `-q` / `--no-pager` / 条件重试、跳过确定性会失败的部分。
3. **确实只能等？** 把超时压到**够用为止**（秒级，例如 30 秒；不要 5 分钟起步）；更长的任务改成后台 job（`run_in_background`）或交给计划任务，然后**继续做别的事**，回来再收结果。

**硬规则**：

- 一个操作如果**大概率要等几分钟**，那它本身就是设计错误——先改做法，再重试；不要靠加长超时让它「稳」。
- 首次请求超过 `timeoutWarnAboveSeconds`（默认 120 秒）的超时会被插件**拒绝一次**；按提示重新规划后重发即可通过。
- 慢调用（默认 > 20 秒）结束后会出现 `**效率监督：上一次调用花了 N 分钟**`，提醒下一步优先并发或换更省的做法。
- 知道会慢的事（大批量下载、全库转码、长轮询）**一开始就按后台任务设计**，并在 `WORKLOG.md` 写清进度与恢复点。
- 不要用「重复轮询」代替等待：先做别的事，再回来查一次；确需轮询就把间隔拉长。

### 0.7 交付纪律：证据链 / 链路三问 / 死循环断路器 / 打包核验（v2.2，2026-11-01）

四条建议全部落成机制，不再是口头要求：

**① 端到端证据链（`proofGate` + `verify_deliverable`，默认开启）**
- 说「已完成 / 已修复 / 已就绪」之前，本轮必须调 `project_docs_write → verify_deliverable`（`summary` + `evidence`）。
- 证据要覆盖三个维度：`request`（客户端视角真实请求：`curl -i` 响应行、ETag、实际字节数）、`file`（物理文件存在与大小：解包后的目录清单，禁止只报 zip 大小）、`env`（部署环境一致性：远端与本机 md5 / 时间戳对照）。缺维度会被拒绝并列出缺哪几维。
- **拦截在回合边界**：模型想用「已完成」收尾而本轮没有登记证据 → 回合不会收尾，模型被 steer 回来补证据或把结论改成「未实测」。证据是按项目记的，旧证据不能给新结论背书（以本轮最后一条用户消息为界）。
- **只对主会话有效（实测限制，2026-11-01）**：子代理在 `turn-stopping` 边界被 steer 后，框架会忽略这次 steer（它的生命周期已结束），最终仍以没证据的原话收尾。所以**子代理的结论要主会话自己核**：看到子代理回报「已完成」，先要求它给出 `curl -i` / 目录清单 / md5 之类的证据，或由主会话自己跑一遍再调 `verify_deliverable`。不要把「子代理说好了」当成交付证据。
- 只读/排查类结论（「找到原因了」）不受限制；写「未实测」也不受限。

**② 链路三问（`linkGuard`，默认开启）**
- 改了部署源（`/var/www`、`dist/`、插件目录、`wwwroot`、`public/`）、打包产物（zip/apk/exe/dll/jar）、或改完要经过缓存层（CDN、`proxy_cache`、Service Worker、ETag）时，**同一次工具结果里会直接附带**一段 `**部署链路提醒：你改动的东西不会自动生效**`，并列出识别到的中间层，要求回答三个问题：谁在消费它 / 消费者去哪里找它 / 中间隔了几道环节。
- 纯本地改动（`src/lib/x.js` 这种）不会触发；同一组中间层 5 分钟内不重复刷屏。

**③ 死循环断路器（`circuitBreaker`，默认开启）**
- 观察两类失败：命令真实报错（`isError`），和用户的负反馈（「还是黑的」「根本没更新」「依然打不开」）。
- 同一失败特征（`failureFingerprint`：去端口/pid/token/哈希/时间的归一化文本）**连续出现 2 次** → 断路器跳闸，进入 **Trace Mode**：所有写操作（`write`/`edit`/`ops_bash`/`pwsh` 等）被拒绝，运行时上下文持续出现 `**死循环断路：同一失败已第 N 次**`。
- 解锁唯一方式：`project_docs_write → trace_report`，`evidence` 里必须带**消费端**「文件:行号」级别的证据（或 access.log / 真实网络包 / 调用栈），只写「我又改了一下代码」不算，会继续被拒。
- 断路器状态按 Agent 持久化在 `storeDir/.breakers/<agent>.json`，重载不丢。

**④ 打包完整性核验（`bundle_check`）**
- 打 zip / 整合包 / 分发目录之后，调 `project_docs_write → bundle_check`（`source_tree` + `archive_tree` 两份清单，`ls -l` 与 `find` 两种格式都能解析，`required_categories` 可点名必含目录）。
- 返回逐条差异：缺哪些文件、哪些分类整块为空、源目录 vs 包内条目数。**文件数一致不等于内容完整**——整块目录漏掉（`assets/`、`kubejs/`）是最常见的失败，报告会把「分类为空」单独列在最前面。
- `.git/`、`node_modules/`、`__pycache__/` 等自动忽略，不用手工过滤。

四个开关都在 `cordis.patch.yml`：`proofGate` / `linkGuard` / `circuitBreaker`（`bundle_check` 是工具，无开关）。系统提示纪律里已同步这四条。

## 1. 新项目：先建库，再写代码

新建项目（或第一次由 Agent 接手一个还没有条目的目录）时，按顺序做：

1. `project_docs` → `list_projects`，确认没有同 root 的条目。
2. `project_docs_write` → `create_project`：
   - `id`：稳定的 ASCII 短 id（小写 + 连字符，如 `my-service`）；
   - `title`：人类可读名字；
   - `root`：项目绝对路径；
   - `summary`：一句话说明；
   - `seed: true`（默认）会生成 `PROJECT.md` 与 `COLLAB.md` 模板。
3. 立刻补全**项目文档** `PROJECT.md`（是什么 / 入口与命令 / 当前状态 / 边界），不许留空模板超过本次会话。
4. 立刻补全**合作文档** `COLLAB.md`（红线、不能动的文件、备份规则、验证口径、占用约定）。
5. 在 **Agent 留言板**留一条 `handoff`：项目已建库、当前状态、下一步。
6. 有可复用脚本就 `register_tool` 到公共工具库。

## 2. 已有项目：先自查，再并入

新来的 Agent 进入已有项目时：

1. `project_docs` → `list_projects`，按当前工作目录 / 项目路径找到条目（取最长前缀匹配）。
2. 没有条目 → 按第 1 节新建；有条目 → 继续。
3. 按顺序读：**项目文档**（现状）→ **合作文档**（红线与占用）→ 需要时才读 **凭证区**（`kind: "credential"`）。不要跳读合作文档。
4. **先查认领**：`project_docs` → `list_claims` 看有没有别的 agent 正在做同一件事；有重叠就先在 Agent 留言板留言协商，**不要直接开工**。
5. `list_messages`（board: `agent`）看最近交接。
6. **登记认领**：开工前用 `project_docs_write` → `claim_work`（`agent` / `scope` / `ttl_minutes`）写清「谁 / 做什么 / 只动哪里」；认领是带过期的租约，收工必须 `release_claim`，否则会挡住别人。
7. 动手。

## 3. 写文档的规矩

- **CAS 写入**：覆盖已有文档前先 `read_doc` 拿 `base_hash`，带 hash 写；hash 不匹配就基于最新内容合并，**不要盲覆盖**。
- **追加用 `append_doc`**：给已有文档加内容（尤其是台账）用 `action: "append_doc"`，它会自动读最新内容 + CAS 写回，不需要手算 hash。
- **分类别乱放**：项目/架构/契约/手册/计划 → 项目文档；红线/占用/交接/台账 → 合作文档；连接参数与密钥 → 凭证区（不要写进项目文档）。
- **时效内容不进 docs**：带日期的进度报告、班次交接、逐日日志、CHANGELOG、重复总结属于「时效内容」，写到 Agent 留言板或按本文第 5 节归档，不要新增为项目文档。
- **凭证例外**：需要连机器 / 调接口时读凭证区，**不外发、不贴进聊天回复、不提交**；轮换后同步副本。

## 4. 收尾验收（没做完不算收尾）

1. 跑验证命令并把**命令与结果**写进项目文档（测试项数、构建产物、实测 URL/行为）；没实测就写「未实测」。
2. 更新项目文档的「当前状态 / 未验证 / 待办」。
3. 有共享资源改动或任务交接：`post_message` 一条 `handoff`（谁、改了什么、验证了什么、下一步、坑）。
4. 新工具 → `register_tool`；文档冲突 → 先合并再写。

### 4.1 长任务进度（刷课 / 迁移 / 批量运维）

- 长任务必须在该项目**合作文档**里维护 `WORKLOG.md` 活台账，**只追加**：开跑时写本轮计划；每个里程碑（完成一个单元 / 弹题 / 报错 / 中断 / 长休 / 收工）追加一行，带时间与结果。
- 追加用 `project_docs_write` → `action: "append_doc"`（`kind: "collab"`、`doc_name: "WORKLOG.md"`），不要手算 hash。
- **「当前进度」以 WORKLOG 最新一条为准**；聊天里的汇报要能从中还原。
- 收工：更新 `WORKLOG.md` 收尾条目 + `PROJECT.md` 当前状态 + Agent 留言板 `handoff`。
- 长任务一律**后台跑**（`run_in_background` / 计划任务），不要用前台长超时等它。

## 5. 归档规则（控制注意力成本）

- 保留：项目/架构说明、契约与验收、API/操作手册、协作红线、活台账、当前计划。
- 归档：带日期的进度报告、班次交接（已过期的）、逐日日志、CHANGELOG、被取代的旧稿、重复总结。
- 操作：把 `docs/<kind>/<name>` 移到 `projects/<id>/archive/<kind>__<name>`，并在该项目的 `CURATION.md` 记录理由（工具：`node curate.mjs <decisions.json> --apply`）。

## 6. 安全与边界

- 不读取、不打印、不提交任何配置/凭据文件；排障只输出键名与结构。
- 改共享文件前备份（`*.bak-<YYYYMMDD>-<主题>`）。
- 破坏性或外部动作（删数据、发消息、发布、付费、重启服务）先向用户确认。
- 用户偏好：中文、先结论后依据、实测优先、速度优先、最小改动。

## 7. 自我完善（纪律可以改，但要走流程）

发现纪律缺口（例如某类文档没地方放、某步骤总被跳过）：

1. 先 `read_doc`（`workspace` / `DISCIPLINE.md`）拿 `base_hash`。
2. 以最小改动补充对应小节；不改已生效的历史结论，只加规则或修正明显错误。
3. 带 `base_hash` 写回（CAS）。
4. 在本页「版本记录」加一行：日期 + 改了什么 + 为什么。
5. 在 Agent 留言板发一条 `note`，标题写「纪律修订」，说明新规则，方便其他 Agent 跟上。
